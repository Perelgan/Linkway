# VPN Desktop

Изображения флагов входят в сборку и доступны без сети. [Flagpedia, общественное достояние](https://flagpedia.net/download/images).

Портативный клиент для Windows 10/11 x64 с русским интерфейсом. Соединения обслуживает официальный Mihomo v1.19.34. В сборку включены Wintun и среда .NET Desktop.

Скачайте `VPNDesktop-win-x64.zip` из [GitHub Releases](https://github.com/Perelgan/VPNDesktop/releases) и распакуйте архив целиком.

## Подключение

1. Откройте `VPNDesktop.exe` в главной папке. Для TUN запустите его от имени администратора.
2. Если серверов ещё нет, нажмите **+** в центре вкладки **Подключение**. Вставьте ключ сервера или HTTP(S)-адрес подписки и нажмите **Добавить**. Добавлять и обновлять ключи и подписки можно во вкладке **Источники**.
3. В **Настройках** выберите режим и при необходимости включите прямой доступ к локальной сети. **PROXY** включает системный прокси. **TUN** направляет трафик через виртуальный адаптер, включая трафик приложений, которые обращаются к сети напрямую.
4. На вкладке **Подключение** выберите сервер в панели под круглой кнопкой, затем нажмите круглую кнопку. **Проверить** в строке проверяет один сервер, а **Проверить все** запускает проверку всей панели. Результат отображается рядом с каждым сервером. Для проверки Mihomo отправляет HTTPS-запрос к `www.gstatic.com/generate_204`, поэтому её можно выполнить и при отключённом VPN.

**Обновить подписки** в панели серверов загружает актуальные списки сразу для всех подписок. При ошибке загрузки сохраняется последний рабочий список.

## Вход в Bedolaga Cabinet

1. Откройте **Аккаунт**. Приложение использует кабинет `https://cabinet.iodtechnologies.store/`.
2. Войдите по email и паролю или нажмите **Войти через Telegram** и подтвердите вход в боте.
3. VPN Desktop загрузит серверы активных подписок и откроет вкладку **Подключение**. Выберите сервер и нажмите круглую кнопку.

При следующем запуске клиент восстановит сохранённую сессию и заново загрузит серверы аккаунта. Сессия защищена Windows DPAPI. Вкладка **Аккаунт** позволяет обновить подписки и выйти.

Клиент использует API кабинета по пути `/api/cabinet`. Кабинет должен выдавать HTTPS-ссылку на подписку в одном из форматов, перечисленных ниже.

## Обновления приложения

В разделе **Настройки → Обновления** можно сохранить адрес публичного репозитория GitHub. **Проверить обновления** запрашивает последний стабильный релиз. **Скачать и установить** сверяет SHA-256 архива с данными GitHub и закрывает отключённый клиент для установки. После завершения откройте `VPNDesktop.exe` снова.

Адрес можно оставить пустым до публикации первого релиза.

Для подписок доступны ручное обновление и локальная копия списка серверов. Профили хранятся в `%LOCALAPPDATA%\VPNDesktop` с шифрованием DPAPI для текущего пользователя. Для работы ядра клиент создаёт временные файлы с параметрами подключения и удаляет их при завершении сеанса или при следующем запуске после аварии.

Папка `Libraries` содержит ядро, драйвер и среду .NET. Файлы локализации Windows-интерфейса находятся в `Languages`. При переносе приложения сохраните эти папки рядом с `VPNDesktop.exe`.

## Форматы и маршрутизация

- Ключи VLESS (включая REALITY и Vision), VMess, Trojan, Shadowsocks, Hysteria2, TUIC и AnyTLS читаются штатным парсером Mihomo. Набор параметров транспорта зависит от версии ядра.
- Подписка может возвращать список URI, список URI в Base64 или Clash/Mihomo YAML с разделом `proxies`. Если YAML также содержит `proxy-groups` и `rules`, клиент показывает категории и использует правила этой подписки.
- По умолчанию Mihomo направляет принятый трафик через выбранный сервер. Опция **Локальная сеть напрямую** добавляет прямой маршрут для частных и link-local адресов и домена `.local` после пользовательских правил.
- При отключении PROXY клиент восстанавливает предыдущие настройки Windows. После принудительного завершения запустите клиент снова, чтобы восстановление повторилось.

[Форматы профилей Mihomo](https://wiki.metacubex.one/en/config/proxy-providers/content/) · [Документация TUN](https://wiki.metacubex.one/en/config/inbound/tun/)

### Профили маршрутизации

1. Выберите основной сервер на вкладке **Подключение**, затем откройте **Маршрутизация**. Создайте профиль или используйте **Основной**.
2. Добавьте правила по EXE, домену, IP, CIDR, порту, GEOIP или GEOSITE. Можно выбрать TCP, UDP или оба протокола. Для приложений доступны списки запущенных и установленных EXE и выбор файла. Установленные EXE берутся из меню «Пуск» и Windows App Paths.
3. Укажите направления для правил и для остального трафика. Правила проверяются сверху вниз, отключённые строки пропускаются. Группа использует первый сервер в порядке списка, прошедший проверку доступности. Разные правила могут одновременно использовать разные серверы из любых добавленных источников.
4. Нажмите **Применить профиль**. При подключении ядро перечитывает правила на прежнем порту и закрывает существующие соединения, чтобы приложения подключились по новым правилам. При ошибке используется предыдущий проверенный профиль. Черновики сохраняются отдельно.
5. В блоке **Активные соединения** выделите соединение и нажмите **Создать правило из соединения**. Редактор может подставить приложение, домен, IP или порт по данным Mihomo.

Во вкладке **Группы** отображаются категории источника выбранного сервера, например YouTube, Steam или Telegram. Нажмите на категорию, выберите маршрут из раскрывшегося списка, затем нажмите **Применить**. Личные правила и исключение локальной сети проверяются раньше правил подписки. Для остального трафика можно оставить маршрут подписки или выбрать свой. Кнопка **Отключить правила** позволяет использовать только правила профиля. Встроенные наборы правил и HTTPS-наборы YAML, text и MRS загружаются перед активацией. [Группы Mihomo](https://wiki.metacubex.one/en/config/proxy-groups/select/) · [Наборы правил Mihomo](https://wiki.metacubex.one/en/config/rule-providers/)

Маршрутом категории может быть конкретный сервер, в том числе из другого источника. Старые резервные группы при открытии или импорте профиля заменяются первым сервером из списка. Кнопки **Добавить своё правило** и **Выбрать существующее правило** направляют подходящий трафик по маршруту выбранной категории. Такое правило привязано к источнику категории. Если выбран другой источник или категория удалена из подписки, совпавший с этим правилом трафик блокируется до перенастройки.

Импорт и экспорт используют JSON VPN Desktop. Файл содержит условия правил, пути приложений и ссылки на серверы. Ключи, URL подписок и токены остаются в хранилище источников. На другом компьютере после импорта может понадобиться заново выбрать серверы и указать местные пути к EXE. Для первого применения GEOIP или GEOSITE Mihomo загружает нужную базу GeoData и проверяет указанные категории. Проверенные базы сохраняются локально.

**PROXY** обрабатывает запросы приложений, которые используют системный прокси или локальный HTTP/SOCKS5-порт Mihomo. UDP в этом режиме доступен приложениям с явным SOCKS5 UDP. Свой DNS, QUIC или прямые соединения приложения могут проходить вне системного прокси. Правило по приложению опирается на процесс, который открыл соединение с Mihomo, в том числе на общий системный процесс, если приложение делегировало ему запрос.

**TUN** перехватывает TCP и UDP для IPv4 и IPv6. Обычные DNS-запросы на порту 53 по TCP и UDP обрабатывает Mihomo. Для запросов назначения используется DoH через основной VPN или другой сервер из активных маршрутов. Для разрешения имён самих VPN-серверов используется отдельный DoH. При недоступности VPN-сервера и при отсутствии поддержки UDP выбранный VPN-маршрут блокирует трафик или использует другой VPN-сервер из явно заданной группы. [Правила Mihomo](https://wiki.metacubex.one/en/config/rules/) · [DNS Mihomo](https://wiki.metacubex.one/en/config/dns/)

**Kill Switch** включается в разделе **Настройки → Маршрутизация** для режима TUN. При подключении Windows ограничивает IPv4/IPv6 соединения приложений интерфейсом TUN. Локальные соединения внутри Windows и сетевые соединения самого Mihomo разрешены, поэтому явные маршруты **Напрямую** в профиле продолжают действовать через Mihomo. После сбоя ядра остаётся блокировка. Доступ можно восстановить переподключением или кнопкой **Снять блокировку сети**. При отключении VPN вручную и при завершении процесса VPN Desktop временные фильтры Windows удаляются. [Windows Filtering Platform](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-layers)

## Сборка

После сборки интеграционные проверки маршрутизации запускаются командой `dotnet run --project .\Source\RoutingTests -c Release`. Тесты используют Mihomo из `Libraries` или `Source\dist\VPNDesktop\Libraries`, локальные тестовые серверы и тестовые базы GeoData. Они не включают системный прокси или TUN.

Из главной папки выполните `pwsh -File .\Source\build.ps1`. Требуются Windows, SDK .NET 10, Go и доступ к GitHub, wintun.net и NuGet. Скрипт проверяет SHA-256 архивов ядра и драйвера и создаёт готовую папку `Source\dist\VPNDesktop`.

Для GitHub Releases задайте номер версии в `Source\VPNDesktop\VPNDesktop.csproj` и запустите `pwsh -File .\Source\build.ps1 -ReleaseArchive`. Скрипт также создаст `Source\dist\VPNDesktop-win-x64.zip`. Прикрепите этот файл к стабильному релизу с тегом версии, например `v1.2.0`.

Mihomo поставляется отдельным неизменённым исполняемым файлом. Его исходный код и лицензия GPL-3.0 доступны в релизе v1.19.34. Лицензии Mihomo и Wintun находятся в папке `Licenses`. [Релиз и исходный код Mihomo](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.34) · [Wintun](https://www.wintun.net/)

В интерфейсе используются иконки Lucide 0.563.0, перенесённые в геометрию WPF. Лицензия входит в сборку как `Licenses\LICENSE-Lucide.txt`. [Исходники и лицензия Lucide](https://github.com/lucide-icons/lucide/tree/0.563.0)
