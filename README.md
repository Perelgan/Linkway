# Linkway

Linkway — портативный VPN-клиент для Windows 10/11 x64 с интеграцией с **Peregar vpn Cabinet**. Войдите в кабинет прямо из приложения, чтобы загрузить серверы из активных VPN-подписок и подключиться.

Клиент использует Mihomo, поддерживает системный прокси и TUN, правила для приложений и доменов и Kill Switch в режиме TUN.

## Запуск

1. Скачайте `VPNDesktop-win-x64.zip`, распакуйте архив целиком и откройте `VPNDesktop.exe`. Для TUN запустите клиент от имени администратора. [Скачать релиз](https://github.com/Perelgan/Linkway/releases/latest)
2. Добавьте ключ или URL VPN-подписки во вкладке **Источники** либо войдите в Peregar vpn Cabinet через **Аккаунт**.
3. Выберите сервер во вкладке **Подключение** и нажмите кнопку подключения.

## Подключение и сетевые настройки

При закрытии Linkway можно свернуть окно в трей, закрыть интерфейс с работающим VPN или отключить VPN и выйти. Галочка в диалоге запоминает выбор. В **Настройки → Запуск и восстановление** можно выбрать другое действие или вернуть диалог. После выхода с работающим VPN следующий запуск Linkway открывает существующий сеанс. Для управления сеансом TUN открывайте Linkway с теми же правами администратора.

Обновление интерфейса на сборки, поддерживающие фоновые сеансы, сохраняет работающий VPN. Новая копия Linkway откроется после установки. Версия работающего ядра меняется при следующем подключении.

На главной панели доступны режим PROXY/TUN, источник, выбранный сервер, время сеанса и график скорости. Скорость загрузки и отправки видна в нижней плашке слева. Пинг маршрута и проверенных серверов отображается при включении **Режима разработчика** в настройках. Светлая и тёмная темы переключаются в **Настройки → Оформление**.

В **Настройки → DNS и выбор сервера** задаётся стратегия основного маршрута. Ручной режим использует выбранный сервер. Автоматический режим выбирает сервер с наименьшей задержкой. Резервирование начинает с выбранного сервера, затем использует остальные по порядку. Балансировка распределяет соединения между доступными серверами. Автоматические стратегии используют до 64 серверов выбранного источника. Правила с явно закреплённым сервером продолжают использовать заданный выход.

В DNS можно указать IP-адрес, DoH (`https://…`) или DoT (`tls://…`). Для раздельного DNS используется одна пара `домен=DNS` на строку. Запросы назначения передаются через VPN-маршрут. Для начального разрешения имён самих VPN-серверов используется отдельный DoH. TUN перехватывает обычный DNS на TCP/UDP 53, а системный прокси охватывает приложения, которые его используют.

Переключатель **Правила подписки** находится под выбором профиля в разделе **Маршрутизация**. Для включения или отключения правил измените положение переключателя и нажмите **Применить**.

При активном VPN кнопка **Применить** обновляет профиль в работающем ядре. Кнопка **Сохранить сетевые настройки** сразу применяет DNS и другие параметры из раздела **DNS и выбор сервера**. Переключатель **Локальная сеть напрямую** действует сразу.

Группа «Недоступные сайты» использует сервер, выбранный в списке **Подключение → Серверы**. При активном VPN выбор другой строки переключает сервер автоматически. Mihomo закрывает открытые сетевые соединения, а новые идут по обновлённым маршрутам. Маршрут остального трафика задаёт профиль Linkway. Подключение и отключение доступны во время проверки серверов.

При обновлении подписки Linkway сохраняет конфигурацию с правилами и показывает их количество в **Маршрутизация → Группы**. Если провайдер возвращает сокращённую версию, клиент пробует форматы Mihomo и Clash. При неполном ответе сохраняется предыдущая полная копия. Если VPN уже подключён, новые правила источника вступят в силу после переподключения.

В поле наборов правил одна строка соответствует одному HTTPS-источнику. Формат строки показан ниже.

```text
https://example.org/domains.txt | domain | text | VPN
```

Поддерживаются типы `classical`, `domain` и `ipcidr`, форматы `yaml`, `text` и `mrs` и выходы `VPN`, `DIRECT` и `REJECT`. Формат `mrs` подходит для `domain` и `ipcidr`. Порядок строк задаёт приоритет после личных правил и исключения локальной сети, перед правилами подписки. При недоступности адреса используется последняя проверенная копия, если она есть. Опция обновления GeoIP и GeoSite использует механизм работающего ядра Mihomo для базы, необходимой активной конфигурации.

## Диагностика и автоматизация

В разделе **Диагностика** можно проверить локальный порт и API Mihomo, DNS A/AAAA, VPN-выход и HTTPS по разным путям. При активном TUN видны выбранные Windows интерфейсы для тестовых IPv4 и IPv6. Для пробных запросов через Mihomo отчёт показывает тип маршрута, если ядро успело зарегистрировать соединение. При активном Kill Switch тест также пробует соединения с тестовыми DNS и IPv6-адресами через физические интерфейсы. При тайм-ауте результат остаётся неопределённым. Отчёт JSON включает версию клиента, режим, состояния, результаты и журнал приложения. Учётные данные, адреса подписок, имена серверов, DNS-ответы и список соединений в отчёт не включаются.

Общий трафик берётся из счётчиков Mihomo. Разбивка по приложениям и выходам учитывает соединения, которые ядро показало во время опроса. История объёмов и длительности выключена по умолчанию. При её включении сохраняются последние 100 сеансов с защитой Windows DPAPI. Отключение истории удаляет прежние записи.

В настройках запуска можно включить автозапуск Windows, автоподключение, восстановление после сна, смены сети и сбоя, а также сворачивание в трей. Для TUN по-прежнему требуются права администратора. Сочетание **Ctrl+Alt+L** открывает окно, если оно свободно. Из меню трея доступны подключение, отключение, диагностика и выход.

В **Диагностика → Проверка маршрута** введите домен, IP-адрес или URL. Linkway открывает тестовое TCP-соединение через прокси активного Mihomo и показывает сработавшее правило, выход и группу, если ядро их зафиксировало. Правила для конкретного приложения и обработка UDP могут дать другой маршрут.

Кнопки **Проверить** и **Проверить все** в списке серверов измеряют время прямого TCP-подключения к адресу и порту сервера. При активном TUN замер привязан к обычному сетевому интерфейсу Windows. Kill Switch блокирует прямой замер, а для узлов только с UDP задержка TCP недоступна.

В **Настройки → Запуск и восстановление** включите **Подключать VPN при входе в Windows**, сохраните настройки и подтвердите права администратора. Планировщик запускает Linkway в трее при входе в эту учётную запись, с последним сохранённым режимом PROXY или TUN. Эта опция заменяет обычный автозапуск окна. Если перенесёте портативную папку, сохраните эту настройку из нового расположения.

## Обновления

В **Настройки → Обновления** нажмите на нужный канал. Клиент покажет сохранённый список и обновит его с GitHub. Чтобы заново загрузить список текущего канала, нажмите **Проверить обновления**. Экспериментальный канал включает предварительные релизы. Выберите **Последняя версия** или конкретную сборку, отключите VPN и нажмите **Установить сборку**. [Все релизы](https://github.com/Perelgan/Linkway/releases)

В **Настройки → Обновления → Ядро Mihomo** можно выбрать комплектное ядро или официальную стабильную Windows x64-сборку, начиная с v1.19.33. Linkway сверяет SHA-256 загруженного архива и проверяет запуск ядра перед выбором. Перед сменой ядра отключите VPN. Выбранная версия хранится в папке Cores рядом с VPNDesktop.exe.

Начиная с 1.4.0-beta.7, для релизов со списком файлов Linkway скачивает из архива только изменившиеся файлы и сверяет их по SHA-256. Для старых релизов и сетей без поддержки HTTP Range используется полный архив. Одинаковые файлы остаются на месте, а после успешной установки Linkway снова открывается. При первом переходе со старого лаунчера откройте VPNDesktop.exe вручную.

При переходе с версии `1.3.1` или ниже скачайте архив вручную. В этих версиях для обновлений используется прежний адрес GitHub.

## Сборка

Требуются Windows, SDK .NET 10 и Go. Команды запускаются из корня репозитория.

```powershell
pwsh -File .\Source\build.ps1 -ReleaseArchive
dotnet run --project .\Source\RoutingTests -c Release
dotnet run --project .\Source\RoutingTests -c Release -- --ui
```

Рядом с архивом `VPNDesktop-win-x64.zip` создаётся индекс `VPNDesktop-win-x64.files.json`. Загрузите оба файла в один GitHub-релиз. Тег GitHub должен совпадать с версией сборки с добавлением префикса `v`.

### Нумерация релизов

Стабильные версии используют формат `MAJOR.MINOR`, например `1.4`. Экспериментальные сборки используют `MAJOR.MINOR-beta.N`, где `N` увеличивается с каждой сборкой серии. Например, версия `1.4-beta.25` опубликована с тегом `v1.4-beta.25`.

Среднее обновление повышает второе число, например до `1.5`. Крупное обновление повышает первое и сбрасывает второе, например до `2.0`. При начале новой серии беты нумеруются с `beta.1`. На GitHub они помечаются как предварительные (*pre-release*).

Для обновления из старых клиентов опубликована переходная сборка `1.4-beta.24` с техническим тегом `v1.4.5-beta.24`. Для упаковки этого архива задаётся `LinkwayLegacyVersion=1.4.5-beta.24`. Обычная сборка использует двухкомпонентную версию из файла проекта. Старые теги и ссылки на архивы продолжают работать.
