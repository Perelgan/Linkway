# Linkway

Linkway — портативный VPN-клиент для Windows 10/11 x64 с интеграцией с **Peregar vpn Cabinet**. Войдите в кабинет прямо из приложения, чтобы загрузить серверы из активных VPN-подписок и подключиться.

Клиент использует Mihomo, поддерживает системный прокси и TUN, правила для приложений и доменов и Kill Switch в режиме TUN.

## Запуск

1. Скачайте `VPNDesktop-win-x64.zip`, распакуйте архив целиком и откройте `VPNDesktop.exe`. Для TUN запустите клиент от имени администратора. [Скачать релиз](https://github.com/Perelgan/Linkway/releases/latest)
2. Добавьте ключ или URL VPN-подписки во вкладке **Источники** либо войдите в Peregar vpn Cabinet через **Аккаунт**.
3. Выберите сервер во вкладке **Подключение** и нажмите кнопку подключения.

## Подключение и сетевые настройки

На главной панели доступны режим PROXY/TUN, источник и выбранный сервер, проверка задержки, время текущего сеанса и скорость загрузки и отправки. Светлая и тёмная темы переключаются в **Настройки → Оформление**.

В **Настройки → DNS и выбор сервера** задаётся стратегия основного маршрута. Ручной режим использует выбранный сервер. Автоматический режим выбирает сервер с наименьшей задержкой. Резервирование начинает с выбранного сервера, затем использует остальные по порядку. Балансировка распределяет соединения между доступными серверами. Автоматические стратегии используют до 64 серверов выбранного источника. Правила с явно закреплённым сервером продолжают использовать заданный выход.

В DNS можно указать IP-адрес, DoH (`https://…`) или DoT (`tls://…`). Для раздельного DNS используется одна пара `домен=DNS` на строку. Запросы назначения передаются через VPN-маршрут. Для начального разрешения имён самих VPN-серверов используется отдельный DoH. TUN перехватывает обычный DNS на TCP/UDP 53, а системный прокси охватывает приложения, которые его используют.

В поле наборов правил одна строка соответствует одному HTTPS-источнику. Формат строки показан ниже.

```text
https://example.org/domains.txt | domain | text | VPN
```

Поддерживаются типы `classical`, `domain` и `ipcidr`, форматы `yaml`, `text` и `mrs` и выходы `VPN`, `DIRECT` и `REJECT`. Формат `mrs` подходит для `domain` и `ipcidr`. Порядок строк задаёт приоритет после личных правил и исключения локальной сети, перед правилами подписки. При недоступности адреса используется последняя проверенная копия, если она есть. Опция обновления GeoIP и GeoSite использует механизм работающего ядра Mihomo для базы, необходимой активной конфигурации.

## Диагностика и автоматизация

В разделе **Диагностика** можно проверить HTTPS, DNS и доступность VPN-выхода. При активном Kill Switch тест также пробует соединения с тестовыми DNS и IPv6-адресами через физические интерфейсы. При тайм-ауте результат остаётся неопределённым. Отчёт JSON включает версию клиента, режим, состояния, результаты и журнал приложения. Учётные данные, адреса подписок, имена серверов, DNS-ответы и список соединений в отчёт не включаются.

Общий трафик берётся из счётчиков Mihomo. Разбивка по приложениям и выходам учитывает соединения, которые ядро показало во время опроса. История объёмов и длительности выключена по умолчанию. При её включении сохраняются последние 100 сеансов с защитой Windows DPAPI. Отключение истории удаляет прежние записи.

В настройках запуска можно включить автозапуск Windows, автоподключение, восстановление после сна, смены сети и сбоя, а также сворачивание в трей. Для TUN по-прежнему требуются права администратора. Сочетание **Ctrl+Alt+L** открывает окно, если оно свободно. Из меню трея доступны подключение, отключение, диагностика и выход.

## Обновления

В **Настройки → Обновления** нажмите на нужный канал. Клиент покажет сохранённый список и обновит его с GitHub. Экспериментальный канал включает предварительные релизы. Выберите **Последняя версия** или конкретную сборку, отключите VPN и нажмите **Установить сборку**. [Все релизы](https://github.com/Perelgan/Linkway/releases)

При переходе с версии `1.3.1` или ниже скачайте архив вручную. В этих версиях для обновлений используется прежний адрес GitHub.

## Сборка

Требуются Windows, SDK .NET 10 и Go. Команды запускаются из корня репозитория.

```powershell
pwsh -File .\Source\build.ps1 -ReleaseArchive
dotnet run --project .\Source\RoutingTests -c Release
dotnet run --project .\Source\RoutingTests -c Release -- --ui
```

Готовый архив появится в `Source\dist\VPNDesktop-win-x64.zip`. Тег GitHub должен совпадать с версией сборки с добавлением префикса `v`.

### Нумерация релизов

- **Малые изменения** повышают третье число и выходят только в экспериментальном канале. От `1.3.3` следующий малый выпуск — `1.3.4-beta.1`. Повторная сборка того же выпуска — `1.3.4-beta.2`, следующее самостоятельное малое изменение — `1.3.5-beta.1`.
- **Средние обновления** повышают второе число и сбрасывают третье. Следующий пример — `1.4.0`. Проверенные малые изменения можно включить в этот выпуск.
- **Крупные обновления** повышают первое число и сбрасывают остальные. Следующий пример — `2.0.0`.

Средние и крупные обновления обычно выходят в стабильном канале. Если нужна обкатка, сначала выпускается бета, например `1.4.0-beta.1`, затем стабильная `1.4.0`. На GitHub все сборки с суффиксом `-beta.N` помечаются как предварительные (*pre-release*).
